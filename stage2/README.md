## Входные данные и настройки

- Оба потока содержат те же 13 923 запроса в том же порядке, 6 154 754 входных и 577 752 выходных токена. Из каждого времени вычтено 1 382 400 с, чтобы `arrived_at` отсчитывался от начала суток 16. Длины и интервалы сохранены. [Исходный поток](../stage1/day16_real.csv) · [Равномерный поток](../stage1/day16_uniform.csv)
- Лимит `вход + выход` в проигрывателе и предикторе — 8 192 токена. Максимум в данных — 4 097, исключено 0 запросов в каждом потоке. [Карточка модели](https://huggingface.co/meta-llama/Meta-Llama-3-8B#model-details)
- Одна реплика обслуживается одной GPU (`TP=1`, `PP=1`). Маршрутизация по кругу, планировщик Sarathi, максимум 128 запросов в батче, блок prefill до 512 токенов за итерацию. Все реплики доступны с начала до завершения прогона.
- Предиктор Vidur обучен на готовых `mlp.csv` и `attention.csv`. Для всех прогонов зафиксированы 100 деревьев, максимальная глубина 16 и кросс-валидация на трёх частях выборки для одной комбинации параметров. Накладные расходы CPU не моделировались, как в стандартной конфигурации Vidur. [Конфигурация](config.json)

## Пробный прогон

На одной реплике Vidur завершил все 24 запроса, взятые из начала минуты 17:38 исходного потока. У всех 24 TTFT уложилась в 2 с. P95 составил 0,295 с. Выгрузка Vidur подтвердила длины входа и выхода каждого запроса.

## Метрики

TTFT берётся из `prefill_e2e_time` Vidur — от прихода запроса до первого токена, включая очередь. Критерий — доля `TTFT ≤ 2 с` не ниже 95% среди всех поданных запросов. P95 — значение на позиции `ceil(0,95 × N)` после сортировки. Запросы без итоговой метрики первого токена учитываются как не уложившиеся в лимит.

TPOT показывает среднее время на токен после первого для каждого запроса. Оно рассчитано из двух метрик Vidur как `(request_e2e_time − prefill_e2e_time) / (число выходных токенов − 1)`. P50 и P95 TPOT рассчитаны среди завершённых запросов с как минимум двумя выходными токенами. [Описание метрик Vidur](https://github.com/microsoft/vidur/blob/abae7f63aa857300f5cdc6f5e0d27860cd24721b/docs/metrics.md)

**Одной GPU хватило для обоих потоков.** Все запросы уложились в 2 с, поэтому выравнивание не изменило потребность в GPU по критерию пилота. В исходном потоке вторая GPU снизила P95 TTFT примерно на 21 мс, а в равномерном измеренные P95 TTFT и P50/P95 TPOT совпали.

## Воспроизведение

Из корня `Economics-analysis` в окружении Python 3.10 выполните команды ниже. В рабочей папке будут сохранены входы для Vidur, его журналы, выгрузки метрик и `results.csv`.

```sh
git clone https://github.com/microsoft/vidur.git ../vidur
git -C ../vidur checkout abae7f63aa857300f5cdc6f5e0d27860cd24721b
python -m pip install -r stage2/requirements.txt
python stage2/run_experiment.py smoke --vidur ../vidur --work-dir ../vidur-runs
python stage2/run_experiment.py full --vidur ../vidur --work-dir ../vidur-runs
```
