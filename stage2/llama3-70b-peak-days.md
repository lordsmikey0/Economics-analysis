# Этап 2. Llama 3 70B в пиковые сутки 21 и 22

Сутки 21 выбраны по наибольшему минутному объёму входных токенов среди суток 16–22 (410 317 в 16:41). Сутки 22 выбраны по наибольшему минутному объёму выходных токенов (69 293 в 23:55). [Разбор суток 21](../stage1/peak_reports/day21.md) · [Разбор суток 22](../stage1/peak_reports/day22.md) · [Сравнение за сутки 16](llama3-70b.md#результаты-tp2)

## Данные и условия

Использован тот же `BurstGPT_1.csv` с фильтрами `Model = ChatGPT`, `Log Type = API log` и `Response tokens > 0`. Равномерные времена строятся от начала каждых суток с шагом `86 400 / N` секунд, как для суток 16. Скрипт сверяет строки попарно перед симуляцией. При лимите 8 192 токена на вход и выход исключено **0 запросов** в каждом из четырёх потоков.

Одна реплика Llama 3 70B работает на двух A100 80 ГБ (`TP=2`, `PP=1`). Использованы те же профиль Vidur, планировщик Sarathi, маршрутизация и метрики, что для суток 16. Прогон на четырёх A100 запускается только для потока, который на двух картах не достиг 95% запросов с `TTFT ≤ 2 с`. TTFT включает очередь. Запросы без итоговой метрики первого токена считаются опоздавшими. TPOT измеряется после первого токена для завершённых запросов с как минимум двумя выходными токенами. [Конфигурация](config-70b-tp2.json) · [Базовые настройки](config.json) · [Версия Vidur `abae7f6`](https://github.com/microsoft/vidur/commit/abae7f63aa857300f5cdc6f5e0d27860cd24721b)

Для сравнения, в готовых прогонах суток 16 на двух A100 опоздали 24 из 13 923 запросов в исходном потоке и 0 из 13 923 в равномерном. Оба потока прошли суточный критерий. [Результаты суток 16](results-70b-tp2.csv)

## Воспроизведение

Используйте [окружение этапа 2](README.md#воспроизведение) и [зафиксированный исходный CSV](../README.md#этап-1-сравнение-профилей-нагрузки). Из корня репозитория выполните команду ниже.

```sh
python stage2/run_peak_days.py --source /path/to/BurstGPT_1.csv --vidur ../vidur --work-dir ../vidur-peak-runs --jobs 4
```

Рабочая папка содержит подготовленные пары в `inputs/`, журналы, выгрузки Vidur, а также `results.csv` и `real-windows.csv`. Исходный файл проверен по SHA-256 `46fc9480ef0b748ecb2b51d512ff08c196b031782cbe6f78e28044d768e86d5a`.
